## v0.5.0 — Runtime Observability

The portal could always tell you what *should* be deployed. It could not tell you
what *is* running. This release closes that loop: **intended state from Git,
observed state from the cluster, and one click into the signal that explains the
difference.**

---

## What's New

### Runtime Status *(headline)*

The Runtime tab is now a per-environment panel backed by two real sources, read
with **your** Kubernetes credentials:

- **ArgoCD `Application`** — did CD deliver? Sync state, health, revision, last operation
- **Crossplane `XTenantApp`** — did the platform provision it? Created, ready, live URL, running image

Readiness comes from the composition's own `.status.ready` write-back, not
Crossplane's `Ready` condition, which lags behind reality.

Missing environments are not failures. Each cell reports `not-found` (not
promoted yet), `forbidden` (RBAC prerequisite not applied — see Upgrade Notes) or
`unreachable`. One dead cluster degrades only its own cells.

### Active Alerts

With `ALERTMANAGER_URL` set, the Runtime tab shows what is firing right now —
critical-first, with severity, duration, affected pod, and the rule's runbook
link. One read, no silencing; that stays in Alertmanager's UI.

### Grafana deep links

Every environment row links into Grafana Explore for **logs, traces, CPU, memory
and profiles**, each scoped to that exact service *and* environment.

Scoping matters more than it looks: dev, staging and production share one
namespace and one `app` label, so an unscoped query blends all three. Memory uses
`container_memory_working_set_bytes` — what the OOM killer evaluates — not
`container_memory_usage_bytes`.

Links whose backing URL is unconfigured are hidden. Full selector reference in
[observability.md](https://gitea.xeusnguyen.xyz/platform-team/wxops-portal-v2/src/tag/v0.5.0/docs/platform/observability.md).

### Session recovery without signing out

An expired Pinniped session now shows **"Session expired"** with a **Sign in
again** button instead of a bare `HTTP 401`. It starts a fresh OIDC flow and
returns you to the exact page you were on — nothing is signed out. Wired into the
Runtime tab, Alerts card and Cluster resource tabs.

### Faster-feeling sign-in

Authentication was never the slow part — the callback does one token exchange.
The wait was `/dashboard` having no loading state while its first render blocked
on a cold catalog walk.

- **The dashboard streams** — shell, hero and identity panel paint immediately; stats arrive behind skeletons
- **Auth failures are readable** — a failed callback returns you to the login page with an explanation, not raw JSON
- **The sign-in button acknowledges the click** and blocks repeats, which each used to start a fresh PKCE flow

> The identity-provider pages are not the portal's. The chain is portal →
> Pinniped Supervisor → Dex → Gitea; with one IdP configured the Supervisor
> redirects straight through, so the login form you see is Dex's.

### First test suites

`internal/observability`, `internal/alertmanager` and `internal/auth` ship **25
passing tests** — the first in the repository. They cover deep-link construction
and scoping, query-injection sanitisation, alert filtering, the bounded HTTP
contract, and open-redirect rejection.

## API

Two new read-only endpoints:

```
GET /api/v1/catalog/entities/:kind/:name/environments
GET /api/v1/catalog/entities/:kind/:name/alerts
```

Environment reads use the caller's Pinniped credentials, cached 30s keyed by
session subject — never shared across users.

`/auth/login` accepts an optional `return_to` (same-origin path), stored
server-side with the PKCE verifier so it cannot be altered mid-flow.

**Behaviour change:** `/auth/callback` no longer returns JSON on failure. It
redirects to `/login?error=<code>` with one of `invalid_request`, `expired`,
`server` — opaque codes only, never the underlying OIDC error text. Anything
watching for a `400` from the callback should expect a `302`.

## Security

Full analysis in [security-assurance.md](https://gitea.xeusnguyen.xyz/platform-team/wxops-portal-v2/src/tag/v0.5.0/docs/security/security-assurance.md) §4a–4c.

- **A1 (no cluster writes)** — unchanged. Every new call is a `GET`.
- **A8 (user-scoped RBAC)** — unchanged. A user who cannot `kubectl get application` cannot see it here.
- **A4 (bounded egress)** — **changes only if you enable alerts.** Grafana, Loki, Tempo and Pyroscope are linked to, never called. Alertmanager is the exception, which is why it is opt-in: read-only `GET`, 5s timeout, 50-alert cap, no redirects.

> **Disclosed honestly:** the Alertmanager read is **not user-scoped** —
> Alertmanager has no Kubernetes RBAC, so the portal narrows to one tenant in
> code. That is correctness, not a boundary. Leave `ALERTMANAGER_URL` unset if
> that is unacceptable.

Also documented (§4c): because Loki runs `auth_enabled: false` and Grafana OSS
has no Team Sync, **observability data is shared across tenants**. Only the
Kubernetes API, Vault and Git are tenant-isolated.

`return_to` is treated as hostile input and reduced to a same-origin path —
protocol-relative targets, absolute URLs, backslashes, control characters and
`/auth/*` loops are all rejected to a safe default.

## Upgrade Notes

No migrations. No new *required* variables — everything degrades to "feature
hidden" when unset.

**1. Spoke cluster RBAC — required for live status.** Each tenant needs two
bindings that did not exist before:

- a **`ClusterRoleBinding`** to `tenant-platform-reader` — `XTenantApp` is `scope: Cluster`, so a namespaced RoleBinding cannot reach it
- a **`RoleBinding` in the `argocd` namespace** to `aggregate-argoproj-view` — `Application` CRs live there

`tenant-platform-reader` grants **`get` only, not `list`** — the portal reads by
exact name, so `list` would only let one tenant enumerate another's composites.

Without these, every cell renders "Cluster RBAC not applied" and nothing else
breaks. The portal has no privileged fallback credential.

**2. `NEXT_PUBLIC_ARGOCD_URL` is removed.** Replace with the backend variable
`ARGOCD_URL`; drop the org-level Gitea Actions variable from the workflow.
Changing the URL no longer requires an image rebuild.

**3. New optional variables:**

| Variable | Effect when unset |
|---|---|
| `ARGOCD_URL` | ArgoCD buttons hidden |
| `ARGOCD_NAMESPACE` | Defaults to `argocd` |
| `LGTM_GRAFANA_URL` | All signal links hidden |
| `LGTM_*_DATASOURCE` | kube-prometheus-stack defaults |
| `ALERTMANAGER_URL` | Alerts hidden; no egress added |

If you enable `ALERTMANAGER_URL`, add it to the egress NetworkPolicy
(security-assurance.md §4b).

## Known Limitations

Platform-side, none blocking:

| Limitation | Effect |
|---|---|
| No `ServiceMonitor` for tenant workloads | Metrics show cAdvisor CPU, not app metrics. P95/P99 impossible until something emits a histogram |
| `prometheus.io/scrape` annotations do nothing | Prometheus Operator ignores them without an `additionalScrapeConfig` |
| Prometheus `sampleLimit`/`targetLimit`/`labelLimit` all `0` | One high-cardinality label can degrade monitoring platform-wide |
| Alloy stamps a hardcoded `cluster` label | Log links cannot be scoped per cluster |
| Alertmanager receiver is `null` | Alerts are visible but route nowhere — no paging |
| Only traces flow through Alloy's OTLP pipeline | OTLP logs and metrics are dropped |
| Observability endpoints are global | One Grafana for every cluster |

The metrics gaps are specced for v0.5.1 in
[observability-architecture.md](https://gitea.xeusnguyen.xyz/platform-team/wxops-portal-v2/src/tag/v0.5.0/docs/platform/observability-architecture.md).
